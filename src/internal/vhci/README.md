# Native usbip-win2 client (experimental)

This package talks directly to the public driver API in usbip-win2 `v.0.9.8.0`
(`83bd1f781d57ed6efdf15530c55710cf5d4482bc`). ABI definitions come from
`include/usbip/vhci.h`; retain `../../../LICENSE.usbip-win2.txt` when distributing.
The original upstream BSD notice is unchanged.

`cmd/vhci-control` is a lab CLI. It uses only Go and Windows system APIs;
it does not invoke usbip.exe, libusbip.dll, a driver installer or a VC runtime.
The separately installed signed driver is still required. The existing lab GUI
has not yet been switched to this package.

Only local cables at `127.0.0.1:3240`, bus `1-1` through `1-32`, can be attached.
Attachment uses a single-attempt IOCTL, with no persistent registration. Detach
requires an explicit port and verifies the local experimental `FFFF:CA01`
identity against a fresh snapshot. This is not an atomic ownership lock against
another process changing the port. Do not adopt this experimental identity for
distribution; bind the allocated VID/PID when one is obtained.

Each IOCTL has a cancellation deadline. Cancellation waits for actual kernel
completion before releasing memory, so a malfunctioning kernel request is not
guaranteed to return by the deadline. An attach error is not proof of no state
change; reconcile the device list before deciding what cleanup is required.
Do not blindly retry or detach all ports.

The C++ fixtures in `testdata` were generated by MSVC from the upstream header,
using `PHASE4/tools/vhci_abi_098_20260924.cpp`. Tests compare the Go request bytes
and response interpretation to these independent fixtures and reject malformed
responses and unrelated detach targets.

On 2026-09-24 the native CLI attached, enumerated and detached the expected
device at medium integrity. A four-second audio probe transferred speech.
Device timestamps were still approximately 0.4 times host time. The overall
runner failed because PowerShell 5.1 returned a null server exit code; no exit0
claim is made for that run. This is neither product acceptance nor a timing fix.
Evidence is under `PHASE4/evidence/NATIVE_ATTACH_AUDIO_ONCE_20260924.json`.
